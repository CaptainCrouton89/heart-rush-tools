# Heart Rush deployments

Run `pnpm install` at the repository root, then `pnpm -r build`. Deploy each app with `pnpm --filter rules run deploy`, `pnpm --filter tools run deploy`, or `pnpm --filter play run deploy`. Run `pnpm deploy:all` to deploy all three. (`pnpm --filter rules deploy` invokes pnpm's *workspace package export* command, not the script; use `run deploy`.) The apex redirect is a separate small Worker: `pnpm --filter redirect run deploy`.

Workers use custom domains on the Cloudflare `heartrush.party` zone: `rules`, `tools`, `play`, and an apex redirect to rules. Each app's `wrangler.jsonc` declares its host; a deployment updates that Worker without modifying other apps. `pnpm --filter <app> dev` starts local development: rules port 3910, tools port 3911, play port 3912.

The one Northlight registration is **Heart Rush**, client ID `w5p61c34rt3p` (testing mode; add testers before they sign in). Its redirect URIs are `https://play.heartrush.party/auth/callback`, `https://tools.heartrush.party/auth/callback`, `http://localhost:3912/auth/callback`, and `http://localhost:3911/auth/callback`. No auth routes exist yet. Apps should use `CROUTER_CLIENT_ID` (`w5p61c34rt3p`), `CROUTER_ISSUER` (`https://account.northlight.ai`), and the Worker secret `CROUTER_APP_KEY_JSON` (the JSON contents of `packages/northlight/local/app-key.json`). Both play and tools already have this secret; do not commit the private key. For local work, the key is at `packages/northlight/local/app-key.json`, and `.env.example` is in that package. Configure the SDK with those values explicitly; it does not read the environment itself. The registered app's origin is `http://localhost:3000` (the SDK's initial default); only the four exact redirect URIs listed above are enabled.
